## One write, one epoch

A render store holds nodes. Each node has an expression and a value. The expression is the source of truth, and the value is the cache of its evaluation.

Move the slider. Each move writes a new value to `a`. The store then runs one epoch: it evaluates each reader of `a` in topological order, and it stops at each value that did not change.

<EpochExplorer client:visible title="One write, one epoch" />

Select the button that flips the sign of `a`. The value of `abs(a)` stays the same, thus the epoch does not evaluate `c`. This is the pruning of the epoch.

## What render is

<CardGrid>
  <Card title="Nodes" icon="seti:graphql">
    A node holds an expression and its value. A reference reads another node, or a field of its value. The engine keeps a seat for each read.
  </Card>
  <Card title="Expressions as data" icon="seti:json">
    The IR has three node types: `lit`, `ref` and `app`. The interpreter is total: a failure gives `none` with a cause, and it does not throw.
  </Card>
  <Card title="Classes as templates" icon="puzzle">
    A class gives cells and methods. An instance is an ID and a scope. A change of a class reaches each instance that still follows it.
  </Card>
  <Card title="An interface that renders itself" icon="laptop">
    Render methods are expressions. The viewer shows them as trees that a person can edit, and an edit changes the class at once.
  </Card>
</CardGrid>
